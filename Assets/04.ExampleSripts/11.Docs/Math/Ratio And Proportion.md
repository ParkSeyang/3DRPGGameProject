# 전체에 대한 부분의 관계, 비와 비율

## 비와 비율이란 무엇인가? (비유 + 정의 + 왜 필요한가?)

맛있는 케이크를 만드는 레시피를 상상해봅시다. 레시피에는 '밀가루 2컵, 설탕 1컵'이라고 적혀 있습니다. 
여기서 '밀가루와 설탕의 양은 2 대 1'이라는 관계가 바로 **비(Ratio)** 입니다. 
만약 더 큰 케이크를 만들기 위해 밀가루를 4컵 쓴다면, 맛을 똑같이 유지하기 위해 설탕은 2컵을 넣어야 합니다. 
이처럼 전체 양이 변하더라도 구성 요소 간의 관계를 똑같이 유지하는 것, 이것이 바로 **비례(Proportion)** 의 개념입니다.

게임 개발에서 **비율(Proportion/Rate)** 은 이 개념을 한 단계 발전시킨, 
'전체에 대한 부분의 크기'를 나타내는 값입니다. 체력이 100인 플레이어가 80의 체력을 가졌다면, 
'전체(100)에 대한 부분(80)의 비율'은 0.8, 즉 80%입니다.

정의하자면, **비(Ratio)** 는 두 수량 간의 관계(예: 16:9)를 나타내고, **비율(Proportion)** 은 그 관계를 바탕으로 
'전체' 기준 '부분'의 상대적인 크기를 나타내는 값(예: 0.8)입니다.

이것이 왜 필요할까요? 게임 속 세상의 값들은 제각각입니다. 어떤 캐릭터의 체력은 100이고, 
다른 캐릭터는 5000일 수 있습니다. 하지만 이 두 캐릭터의 체력 바(UI)는 동일한 크기일 수 있습니다. 
이때 '비율' 개념을 사용하면, 실제 체력 값이 얼마든 상관없이 **0.0(0%)에서 1.0(100%) 사이의 값으로 정규화(Normalize)** 
하여 모든 상황에 일관되게 적용할 수 있습니다. 체력 바, 경험치 바, 미니맵 좌표 변환 등 수많은 곳에서 값을 상대적으로 표현하기 
위한 가장 근본적인 수학적 도구입니다.

## 핵심 요약

-   **비(Ratio)**는 두 양의 관계를 나타냅니다. (예: 화면비 16:9)
-   **비율(Proportion)**은 전체에 대한 부분의 크기를 나타내며, 보통 **0.0 ~ 1.0 사이의 값으로 정규화(Normalize)** 하여 사용합니다.
-   `현재값 / 최대값`은 비율을 구하는 가장 기본적인 공식입니다.
-   체력 바의 `fillAmount`, 슬라이더의 `value`, `Lerp`의 `t`값 등 UI와 값의 변화를 다루는 거의 모든 곳에서 비율의 개념이 활용됩니다.

## 세부 개념

### 1. 비율(Proportion)과 정규화(Normalization)

게임 개발에서 가장 중요한 것은 서로 다른 범위의 값들을 일관된 기준으로 다루는 '정규화' 과정입니다. 그리고 그 핵심이 바로 비율입니다.

**정규화 공식: `비율 = (현재값 - 최소값) / (최대값 - 최소값)`**

최소값이 0인 경우가 많으므로, 보통 `비율 = 현재값 / 최대값` 으로 단순화하여 사용합니다.

-   **실용 예제 1 (체력 바)**:
    -   플레이어의 현재 체력이 75, 최대 체력이 150이라고 가정해봅시다.
    -   체력의 비율은 `75 / 150 = 0.5` 입니다.
    -   이 `0.5`라는 값을 체력 바 UI `Image`의 `fillAmount` 속성에 넣어주면, 체력 바가 정확히 절반만 채워진 상태로 표시됩니다.
    ```csharp
    public Image healthBar;
    public float currentHealth = 75f;
    public float maxHealth = 150f;

    void UpdateHealthUI()
    {
        healthBar.fillAmount = currentHealth / maxHealth;
    }
    ```

-   **실용 예제 2 (미니맵 좌표 변환)**:
    -   전체 게임 월드의 크기가 가로 1000, 세로 1000 유닛이라고 합시다.
    -   화면에 표시될 미니맵 UI의 크기는 가로 200, 세로 200 픽셀입니다.
    -   플레이어가 월드 좌표 (X:800, Z:300)에 있다면, 미니맵에는 어디에 표시되어야 할까요?
    1.  X축 비율 계산: `800 / 1000 = 0.8`
    2.  Z축 비율 계산: `300 / 1000 = 0.3`
    3.  미니맵 좌표에 비율 적용:
        -   미니맵 X: `200px * 0.8 = 160px`
        -   미니맵 Y: `200px * 0.3 = 60px`
    -   결과: 플레이어는 미니맵의 (160, 60) 위치에 표시됩니다. 이처럼 거대한 월드와 작은 UI 사이의 좌표를 변환하는 데 비율은 필수적입니다.

### 2. 비례식 (Proportional Expression)

`a : b = c : d` (a 대 b는 c 대 d와 같다) 형태의 비례식은 한쪽의 비율을 알 때 다른 쪽의 값을 유추하는 데 사용됩니다.

-   **실용 예제 (화면 크기에 따른 UI 크기 조절)**:
    -   버튼의 너비가 항상 화면 너비의 20%(1/5)가 되도록 만들고 싶다고 가정해봅시다.
    -   비례식: `버튼 너비 : 화면 너비 = 1 : 5`
    -   수학적으로 `5 * 버튼 너비 = 1 * 화면 너비` 이므로, `버튼 너비 = 화면 너비 / 5` 입니다.
    -   Unity의 `RectTransform` 앵커(Anchor) 시스템이 바로 이 비례식의 원리를 사용합니다. 앵커의 `Min`과 `Max`를 각각 `0.2`, `0.4`로 설정하면, 부모 크기의 20% 지점과 40% 지점 사이를 차지하는, 부모 크기에 비례하여 크기가 변하는 UI를 만들 수 있습니다.

## 주요 Unity 기능과의 관계

비와 비율은 특정 클래스나 함수라기보다는, 아래 기능들의 근간을 이루는 '개념'입니다.

| 기능 | 어떻게 비율을 사용하는가? |
| :--- | :--- |
| **Image.fillAmount** | 0~1 사이의 비율값으로 이미지의 채워진 정도를 결정합니다. |
| **Slider.value** | 슬라이더의 최소/최대값 범위 내에서 현재 핸들의 위치를 0~1 사이의 비율로 나타냅니다. |
| **Mathf.Lerp(a, b, t)** | `t` 매개변수가 바로 0(시작점)과 1(끝점) 사이의 진행 비율을 의미합니다. |
| **RectTransform Anchors** | 부모 RectTransform 크기에 대한 비율로 자신의 위치와 크기를 결정합니다. |
| **AnimationCurve** | 전체 애니메이션 길이를 1로 보고, 특정 시간(비율)에서의 값(value)을 정의합니다. |

## 활용 예시 (실습 브릿지 포함)

**시나리오**: `AsyncOperation`을 사용하여 씬을 비동기 로딩할 때, 로딩 진행률을 표시하는 프로그레스 바를 만들어 봅시다.

1.  `AsyncOperation.progress` 속성은 씬 로딩 진행률을 0.0에서 0.9 사이의 값으로 반환합니다. (씬 활성화 준비가 되면 0.9가 됩니다.)
2.  우리가 UI에 표시할 프로그레스 바는 0.0에서 1.0의 범위를 사용해야 합니다. 즉, `progress` 값의 범위를 `[0.0, 0.9]`에서 `[0.0, 1.0]`으로 재조정해야 합니다.
3.  **비율 계산**: `progress`의 최대값은 0.9이므로, 현재 진행 비율은 `asyncOp.progress / 0.9f` 로 계산할 수 있습니다.
4.  이 계산된 비율 값을 `Slider`의 `value`나 `Image`의 `fillAmount`에 넣어주면, 0.9에서 멈추는 것이 아니라 1.0까지 가득 차는 프로그레스 바를 만들 수 있습니다.
    ```csharp
    IEnumerator LoadSceneAsync(string sceneName)
    {
        AsyncOperation asyncOp = SceneManager.LoadSceneAsync(sceneName);
        
        while (!asyncOp.isDone)
        {
            // asyncOp.progress가 0.9에 도달하면 1.0이 되도록 비율을 조정
            float progress = Mathf.Clamp01(asyncOp.progress / 0.9f);
            loadingSlider.value = progress;
            yield return null;
        }
    }
    ```

이제 여러분은 서로 다른 값의 범위를 '비율'이라는 일관된 기준으로 변환하는 방법을 이해했습니다. 이 개념은 게임 개발 전반에 걸쳐 매우 유용하게 사용됩니다.

1.  **(기초-기억)** 플레이어의 현재 점수는 500점, 목표 점수는 2000점입니다. 목표 달성률을 0과 1 사이의 비율로 계산하는 식을 작성하세요.
2.  **(기초-이해)** 정수(int) 끼리 나눗셈을 할 때 발생할 수 있는 문제점은 무엇이며, C#에서 이를 어떻게 해결해야 하는지 설명하세요. (예: `3 / 4`의 결과)
3.  **(응용-적용)** 자동차의 현재 속도가 `currentSpeed`, 최대 속도가 `maxSpeed`일 때, 속도계 바늘을 0도에서 최대 180도까지 회전시키려고 합니다. `currentSpeed`를 기반으로 바늘의 회전 각도(degree)를 계산하는 함수 `float GetNeedleAngle(float currentSpeed, float maxSpeed)`를 작성해보세요.
4.  **(응용-분석)** `RectTransform`의 앵커 프리셋에서 `middle-right`과 `stretch-right`의 차이점을 '비율'과 '비례'의 관점에서 설명해보세요. 화면 너비가 변할 때 각각 어떻게 다르게 동작할까요?
5.  **(심화-창작)** 2D 횡스크롤 게임에서, 플레이어의 스테이지 진행률을 화면 상단의 프로그레스 바로 표시하는 시스템을 구현해보세요. 스테이지 시작 지점의 X좌표가 `startX`, 끝 지점의 X좌표가 `endX`이고 플레이어의 현재 X좌표가 `playerX`일 때, 프로그레스 바의 `fillAmount` 값을 갱신하는 로직을 작성하세요.

## Note: 주의사항

-   **0으로 나누기 (Division by Zero)**: 비율을 계산할 때 `현재값 / 최대값` 공식을 사용합니다. 이때 `최대값`이 0이 되는 예외적인 상황이 발생하지 않도록 항상 확인해야 합니다. 0으로 나누면 프로그램에 오류가 발생합니다.
-   **정수 나눗셈 (Integer Division)**: C#에서 정수와 정수를 나누면 결과값 역시 소수점 이하가 버려진 정수가 됩니다. 예를 들어 `int a = 80; int b = 100; float c = a / b;` 코드에서 `c`의 값은 `0.8`이 아닌 `0`이 됩니다. 올바른 비율을 얻으려면 최소한 피연산자 중 하나를 `float`으로 만들어주어야 합니다: `float c = (float)a / b;`

## Further Study: 확장 학습

-   **RectTransform Anchors**: Unity UI의 핵심인 앵커 시스템이 어떻게 비율의 원리를 사용하여 해상도에 반응하는 유연한(Flexible) UI를 만드는지 깊이 있게 학습해보세요.
-   **UV 좌표 (UV Coordinates)**: 3D 모델의 텍스처를 입히는 데 사용되는 UV 좌표는 모델의 표면을 2D 평면에 펼쳐놓고, 그 가로(U)와 세로(V) 위치를 0과 1 사이의 비율로 표현한 것입니다. 비율 개념이 그래픽스에서 어떻게 활용되는지 보여주는 대표적인 예시입니다.
-   **벡터 정규화 (Vector Normalization)**: `Vector3.Normalize()` 함수는 벡터의 방향은 유지한 채 크기(길이)를 1로 만드는 연산입니다. 이 또한 '비율'의 개념을 벡터에 적용한 것으로, 순수한 방향 정보가 필요할 때 매우 유용하게 사용됩니다.
